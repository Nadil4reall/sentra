The SENTRA Agent runs locally on the managed Linux server. The Controller authorizes and records operations; profiling and approved enforcement execute on the target.

!
No remote installer or SSH action.

An operator prepares the Linux server and copies the SENTRA release through an operator-controlled method. Never copy the Controller private key or administrator credential to a managed target.

  1. 01 · Prepare Linux server

    Prepare protected paths

    Run these fixed directory commands on the target. The Agent state is private.

    sudo mkdir -p /opt/sentra
sudo mkdir -p /etc/sentra
sudo mkdir -p /var/lib/sentra/agent
sudo chmod 700 /var/lib/sentra/agent
  2. 02 · Install SENTRA files

    Place the research release

    Copy the trusted SENTRA release to /opt/sentra using an operator-controlled method and prepare its Python environment at /opt/sentra/.venv. No apt repository, deb package or automatic installer is provided here.

  3. 03 · Configure Controller trust

    Install the public CA

    Place only the Controller public CA certificate at /etc/sentra/controller-ca.pem. The Agent verifies the Controller HTTPS certificate and hostname. Never transfer a Controller private key or administrator credential.

  4. 04 · Enroll Agent

    Run the first Agent cycle

    Place the temporary bootstrap credential in the protected target-side file /etc/sentra/bootstrap.credential. The bootstrap credential is used only for first enrollment. Replace the URL and release labels below with your approved values; the command contains no secret value.

    cd /opt/sentra
sudo ./.venv/bin/python -m src.agent \
  --controller-url https://CONTROLLER:8443 \
  --controller-ca /etc/sentra/controller-ca.pem \
  --state /var/lib/sentra/agent/state.json \
  --bootstrap-credential-file /etc/sentra/bootstrap.credential \
  --agent-version AGENT_RELEASE \
  --profiler-version m3 \
  --sentra-version CURRENT_RELEASE

    After successful enrollment, remove only the temporary target-side copy:

    sudo rm -f /etc/sentra/bootstrap.credential

    Do not remove the Controller-side enrollment credential. Never display or copy state.json; it stores the Agent's protected Controller-issued identity.

  5. 05 · Verify enrollment

    Run an Agent cycle and inspect the record

    Normal cycles reuse the protected identity, send a heartbeat, poll for constrained work and return a result. The Agent is a one-cycle program, not a daemon. Do not use the bootstrap file argument after enrollment.

    cd /opt/sentra
sudo ./.venv/bin/python -m src.agent \
  --controller-url https://CONTROLLER:8443 \
  --controller-ca /etc/sentra/controller-ca.pem \
  --state /var/lib/sentra/agent/state.json \
  --agent-version AGENT_RELEASE \
  --profiler-version m3 \
  --sentra-version CURRENT_RELEASE
